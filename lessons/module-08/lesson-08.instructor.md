# Instructor notes — 08.8 The service simulation: a full rush

- **Objective:** module practical piece. Plan a shift; `practice` warm-up; two `rush` runs with a service debrief and one change between them; optional `stockout`; six-ticket home mini-rush with alcohol-free drinks.
- **Simulation contract:** the preset table in this lesson is canonical for `service-sim` (with the time table and scoring rules in 08.5). `rush`: 20 tickets, 1–4 drinks incl. rounds of 3–4 of one drink, Module 5 menu + Tom Collins, Paloma, Cuba Libre, French 75, draught beer, house wine; waves of 6 (min 0–3), 6 (min 3–10), 8 (min 10–18); a server's table ticket and bar tickets arrive together; one correct drink is sent back (remake = waste, not inaccuracy). Targets ≥ 90%, ≤ 300 s, ≤ 5%.
- **Likely confusion:** why the rush time target (300 s) is looser than practice (150 s). The first wave is deliberate overload; the skill is fair, short waits with correct drinks.
- **Misconception:** "speed means clicking fast". The model counts fixed action times; only decisions and sequence change the result.
- **Expected hands-on result:** run 1 about 80–90% and 300–400 s; run 2 meets targets when the change targets the biggest cause (usually dead drinks). Home mini-rush tickets 60–120 s.
- **Extension:** run the rush with a fixed seed twice using two different single changes and compare which moved the numbers more.
